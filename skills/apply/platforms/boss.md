# BOSS 直聘（zhipin.com）

页面会改版。以下是已观察到的情况，操作时以当前页面为准；与这里不符时按实际页面判断，并在汇报中注明差异。

## 访问方式

- 从 `https://www.zhipin.com/` 或本人提供、核对过域名的职位链接进入。
- **不要用 CDP / Playwright**：会被重定向到 `_security_check`，随后页面空白（2026-10-28 实测）。用本人日常的浏览器窗口，经辅助功能树或桌面 UI 工具操作。
- 账号名在页面右上角头像附近，与 `job-wingman.json` 的 `displayName` 核对。

## 职位列表与详情

- 搜索结果靠滚动懒加载，滚到底部才会出现更多职位；没有更多时停止。
- 点击职位后详情在右侧面板打开，**地址栏不变**。
- 职位卡片的职位名带链接，形如 `https://www.zhipin.com/job_detail/<id>.html`，`<id>` 即 `jobId`（2026-10-28 本人确认）。通过辅助功能树读取链接地址；读不到时 `jobUrl`、`jobId` 记 `null`，不猜测、不拼接。
- 列表链接不可读或复制链接菜单不可用时，`jobUrl`、`jobId` 记 null，不通过其他接口补取。独立职位页可从可见地址栏读取；按 job 去重而缺 ID 时按 ledger 规则处理，不猜测。薪资以可核对的详情为准。
- 链接可能带 `lid`、`securityId` 等随会话变化的参数；直接交给 `ledger append`，它会去掉。
- 公司名在列表和详情中通常显示简称；按页面原文记录，停止名单靠别名匹配。
- `recruiter` 只写「姓名(职务)」，如 `张先生(人事行政专员)`；不要把时间、公司名、`[送达]` 或消息摘要抄进去。

## 招聘者活跃标签

职位详情中招聘者姓名右侧显示活跃标签（部分列表卡片也会显示）。换算成距今天数：

| 标签 | 天数 |
|---|---|
| 在线、刚刚活跃、今日活跃 | 0 |
| 3日内活跃 | 3 |
| 本周活跃 | 7 |
| 2周内活跃 | 14 |
| 本月活跃 | 30 |
| 2月内活跃、3月内活跃、半年前活跃等 | 按字面换算（60、90、180……） |

遇到表中没有的标签，按字面取保守（较大）的天数，并在汇报中注明，以便补充本表。没有标签视为未知。

## 薪资原文

常见写法：`8-13K`（月薪千元）、`8-13K·13薪`（13 薪不计入月薪比较）、`150-200元/天`（日薪，不直接当月薪）、`面议`（未知）。

**搜索结果列表里的薪资，在辅助功能树中可能显示为特殊字符**，读不出数字（2026-10-29 实测）。遇到时用截图核实，或以职位详情中的薪资为准；读不清就记为未知，不根据乱码推测。

## 沟通按钮

| 按钮 | 含义 | 处理 |
|---|---|---|
| 立即沟通 | 尚未联系 | **视为可能立刻发送消息**，点击前必须先写 `pending` |
| 继续沟通 | 已有会话 | 记 `already_contacted`，不点击 |

## 自动打招呼

BOSS App 中可以关闭「自动打招呼」；运行前按本人当前账号设置确认。

- **已关闭（推荐）**：点击「立即沟通」后进入空白会话，没有自动消息，输入框可用；由 Agent 输入招呼语后发送（2026-10-29 实测确认）。
- **仍开启**：点击「立即沟通」后，账号设置的默认招呼语自动发出。

## 两个入口的差异（2026-10-29 实测）

| 从哪里点「立即沟通」 | 点击后 | 处理 |
|---|---|---|
| 搜索结果页（右侧详情面板） | 进入空白会话，输入框可用 | 直接输入、核对、`guard` 后发送 |
| 独立职位页（`job_detail` 链接打开的页面） | 弹出聊天浮层；**尚未发送时，背景里的按钮就已变成「继续沟通」**。浮层里的「发送」可能没有可操作的辅助功能按钮 | 浮层发送不可操作时，转到「消息」页，按招聘者、公司、职位找到同一个会话，确认其中没有我方消息，再输入、`guard`、发送 |

- 优先从搜索结果页发起，步骤最少。
- 独立职位页上按钮变成「继续沟通」，是本次点击造成的，**不代表之前联系过**；不要据此把当前尝试记为 `already_contacted`。「已联系」只在点击前判断。
- 点击之后尽量把这一条发完（必要时经消息页）。如果放弃发送，该职位此后会一直显示「继续沟通」，以后的运行会把它当作已联系而跳过；这种情况要在汇报中写明，由本人决定是否手动发送。

## 工具超时

点击「立即沟通」或「发送」后，桌面工具超时、重置或切走了前台标签页，就无法确认是否已发出：记 `uncertain`，停止整轮，请本人核对（2026-10-29 实测遇到过一次，本人核对后为「未发出」）。不要重新读取页面后自行判定为「未发出」。

无论哪种，确认已发送的依据都是：会话中出现本次新消息，显示「已送达」或「已读」；或页面给出针对当前职位的发送成功提示。仅进入聊天页、按钮变化不算。

## 输入与发送

- 核对会话标题中的公司、招聘者与当前目标一致后再输入。
- 切换会话后文字可能残留，草稿归属无法从输入框判断；所有 runtime 都先核对会话再读写，未知内容不自动清空、停止该操作并按通用契约收尾，不发送残留内容。
- 聊天输入框的本地控件标识曾为 `chat-input`；这是页面定位事实，不是指定工具调用，操作时须重新核对。「发送」在空输入框时也 enabled，不能据此判断有内容。
- 输入后先单独核对编辑框中的完整文字（防止中文输入被截断），再单独点击发送；不把输入和发送合成一步。
- 一次只发一条，不拆成多个气泡。

## 消息列表

列表「草稿」标记表示有未发送内容，所有 runtime 都跳过该会话并汇报，不清除。聊天列表中每个会话显示招聘者、公司，会话标题中通常能看到对应职位。可用于核对 `uncertain` 的尝试：消息列表中出现该会话且本次招呼语显示「送达」，即可由本人确认后补记 `sent`。
