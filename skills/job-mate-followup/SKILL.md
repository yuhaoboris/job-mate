# 职伴：处理 HR 消息

先读 [就绪流程](references/onboarding.md)，复用已有资料，缺资料就在本任务内补齐。执行前读 [页面与外发规则](references/boss.md)；使用 [数据命令](references/protocol.md) 记录历史与外发。不需要先安装或运行 apply/setup。

## 按会话完成闭环

1. 核对当前资料、账号、本轮范围、未解决发送和待决定事项。只定位本轮允许处理的相关会话，取得稳定标识后 `begin`；不先巡检其他会话。按实际授权选择回复、发简历或主动跟进。仅查看或导入历史时用 `noSend:true`，“只处理这家公司”同时固定 targets 与数量。
2. 读完整的相关会话和当前职位信息，用页面稳定标识建立 threadKey。对照快照中的会话 history。回填历史时，按[历史消息导入](references/protocol.md#历史消息导入)核对双方消息、原始时间和已有事件，调用 `import_history`，包括求职者本人发起的招呼和跟进。新增来信若只需记录摘要，可用 `record:inbound`，复用原消息 messageKey。
3. 对照简历来源和用户已确认的事实回答。未知经历、年限、到岗日期等需询问，不从行业常识补造。薪资期望的陈述与接受对方具体报价不同。
4. 无授权时起草并 `decide`。面试时间的提出/接受/改期、薪资/Offer 承诺、实际交换电话或微信、出差/驻场承诺、付款和证件请求，一律记录待决定事项。即使有一般回复授权，也不能代替本人作决定。用户批准的外发原文通过 `answer` 保存，prepare 绑定 decisionId，逐字发送。
5. 对方明确索要且本人允许时才发送已确认简历；核对原件 SHA-256、平台附件名与预览。平台附件不对应原件时先请本人处理，不凭相似文件名认定一致。上传不等于发送成功。
6. 主动跟进只面向既有会话且需 nudge 授权。先核对并入账影响跟进的历史，确认最近沟通时间及最近一次来信后的已发跟进次数。至少间隔三天、最多两次未回复跟进。任一项无法确认，或会话已拒绝、已结束、已获答复或没有具体沟通目的时，跳过主动跟进。
7. 每次外发遵守 `prepare → guard → 页面动作 → finish`。不明就停，不重试。收到面试邀请记录 `observe:interview_invited`，由用户决定时间；有一般回复授权时可发送不承诺时间的中性回执，否则只起草。
8. `end` 后在当前对话报告本轮适用结果。导入时报告新增、回填、已存在及无法核实的消息。处理会话时报告收到什么、已送达什么、等待谁决定。工作台显示同一批待办；定时任务由宿主能力承担。
