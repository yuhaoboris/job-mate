# 职伴：找岗位与首次沟通

先读 [就绪流程](references/onboarding.md)，复用已有资料；缺资料就在本任务内补齐，完成后继续原任务，不让用户寻找 setup。当前只支持 BOSS 直聘。用户说“筛选简历”但实际在找工作时，按筛选职位理解，必要时澄清角色。

执行前读 [页面与外发规则](references/boss.md)；记录和发送使用 [数据命令](references/protocol.md)。命令均由 Agent 操作，不要求用户编辑 JSON 或运行脚本。首次发现没有本机桌面能力时说明缺口，可以先筛选用户提供的 JD。

## 按职位完成闭环

1. 结合已确认偏好和本轮要求，明确搜索范围、详情预算（默认最多 50 个）和结束条件。本轮只看优先于长期授权。`begin` 固定本轮动作、账号、目标与数量，默认只筛选。用户已经明确授权的范围不逐职位重复询问。
2. 在日常已登录的可见浏览器确认账号，按职位 × 城市优先级搜索。列表能明确排除的先排除；进入详情后记录职位、公司、薪资原文、招聘者活跃标签、职责要求和可见链接/ID。
3. 按实际职责匹配事实，记录每个已读详情的 `screen`。目标职责、地点、薪资门槛、硬要求必须有依据；未知为 `pending`。排除项明确命中才排除，不将“没写外包”当成“已证实非外包”。招聘者超过七天未活跃或活跃状态未知时，不自动联系。
4. 同公司已有联系记录先回到既有会话核对。合格职位按偏好、证据充分程度和招聘者活跃度排序；不编造匹配百分比、不降低条件凑数。
5. 有授权才写简短招呼：选 JD 的一两个具体需求，与简历中的可证实经历相连。不捏造能力、经验年限、数字；没有证据就不写。完成 `prepare → guard → 页面动作 → finish`。进入会话可能自动发送，必须先 guard；有自动招呼就记录实际原文，不再自动补一条介绍。只筛选不点击沟通入口。
6. 遇验证码、限制、身份不符、旧草稿、工具失控或发送不明时停止。每个尝试都回填结果，最后 `end`；无法确定是否发送就保留 `uncertain`，不换工具或新尝试重发。

报告实际筛选、合格、待确认、排除与已确认送达数，列出重点岗位、待决定事项、已覆盖的搜索组合和停止原因。没搜完不能宣称没有岗位。HR 回复属于 `job-mate-followup`；没有安装该技能时，保留待办并说明如何单独安装，不冒充已经处理。
