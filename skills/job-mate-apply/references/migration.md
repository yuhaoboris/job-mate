# 从 1.0 迁移

不自动覆盖旧数据，不在旧目录建立新数据库。用户明确升级已有工作区时，Agent 运行随包 `scripts/migrate.py --source <旧目录> --target <新目录>`。工具保留旧目录，复制相关原始文件到新目录的 `legacy/`，导入可识别沟通记录；旧授权不导入，新工作区暂停且未配置。

迁移工具遇到坏行、未知事件或符号链接会停止，并列出错误位置，不将半份历史当完成。旧事实、偏好、停止名单和简历仍在 legacy 中，由 Agent 完整读取并按新格式向用户简短回显确认；停止名单须映射到 exclusions，不能丢弃。原件只复制一次；用 stage_resume 登记 legacy 中正确的原件，再 configure。

历史中的不明外发保留恢复事项。旧锁也会阻止默认继续：先确认旧执行器已停止，再在新工作区逐个核对不明结果。账户以旧记录的 account 值保留，必须与页面账号核对；不能可靠映射时另请本人确认，不改写历史身份来凑匹配。所有核对完成后本人决定是否解除暂停，按当前请求重新授予动作。

不要删除旧目录；至少保留到用户确认资料、记录、停止名单与账号完整。此迁移只承接已支持的两种 1.0 格式，不保证未知第三方修改的工作区可自动转换。
