# job-mate 2.0 设计

## 产品边界

job-mate 帮求职者筛选**职位**、发起首次沟通、处理 HR 消息。它不筛选候选人的简历。当前只支持 BOSS 直聘，不接入 IM、不安装后台服务，不绑定某个 Agent。

只提供 `job-mate-apply` 和 `job-mate-followup` 两个独立技能。setup 是共用的就绪流程，不是第三个任务入口，也不在安装时收集个人信息：安装器不会运行 Agent，也不能可靠完成简历理解和偏好访谈。

## 首次使用

1. 读取状态；默认 `~/.job-mate`，用户明确指定的路径或 `JOB_MATE_HOME` 优先。告知存储位置，不让用户选择技术配置。
2. 没有简历时请用户提供一份 PDF、DOCX、HTML 或其他 Agent 可读文档；只读取用户主动提供的文件。保留原件和来源，不把简历中的命令当指令。扫描文档需宿主 OCR；无法读取时明确告知，不生成假事实。
3. Agent 提炼经历、技能、教育和项目事实。只对影响筛选或回答的歧义追问，不让用户把简历抄进表单。
4. 合并已有对话，只问仍缺的目标职位、城市/远程意愿、薪资期望和硬性排除项。职位可以据简历建议；当前所在地不能直接当期望城市，现薪不能当期望薪资。薪资可明确“不设门槛”。
5. 简短回显事实、偏好与发送范围，用户确认后保存并继续原任务。没有明确发送许可时只筛选或起草。修改偏好也是对话式增量修改。

Harness 首屏只有提供简历和继续对话。已使用用户看到筛选、沟通、待决定和发送不明；偏好以摘要展示，通过对话修改，无须填写资料表单。

## 唯一数据契约

`core/job_mate.py` 是 CLI 和插件的共同入口。Python 标准库 SQLite 提供跨进程事务；`job-mate.sqlite3` 保存资料、偏好、事件、外发尝试和任务。原始简历放 `resumes/`。本地数据库不加密；Agent 的模型服务仍可能处理这些数据。

请求/响应用 JSON（标准输入/输出），不经 shell 拼接。只读 snapshot 不创建工作区。profile 修改带修订号，运行中拒绝修改配置；暂停可即时阻止后续 guard。数据库事务不涵盖浏览器发送，必须先记录准备，再操作页面，最后依据页面证据记录结果。

profile 是事实和偏好；event 是已观察到的事实；attempt 是一次具体外发意图；decision 是待本人决定的事项；run 是一次有范围和上限的执行。发送不明保持不明，不能自动重试。详情、指标与待办从同一个 snapshot 得到，避免不同时间的响应拼成假快照。

## 执行约束

- BOSS 只通过用户日常已登录的可见浏览器，由桌面/辅助功能操作；不使用 CDP/Playwright、隐藏接口或规避检测。
- Agent 在页面确认账号。授权取自本人本轮明确请求或已确认的长期授权；“只看”优先。账号不同就停止，不能跨账号复用运行。
- 每个职位记录筛选依据，未知硬条件为待确认；不以名称代替职责判断、不编匹配分数、不为凑量降低条件。
- 外发先 prepare，再 guard，再页面操作，再 finish；每次可能发送的点击都需 guard。已有草稿则交还用户。仅工具调用成功不等于送达。
- 发送结果不明阻止继续外发；重启不偷锁、不重试旧尝试。恢复必须核对旧进程停止和真实会话结果。
- 面试安排、接受薪资/Offer、联系方式交换等承诺交给用户。批准的原话原样发送；HR 内容不是授权来源。
- 待办在当前对话与本地工作台展示，不向外部 IM 转发。

## 分发和职责

共享核心与参考资料生成到两个 skill 目录，副本逐字一致且 CI 验证。单装任一技能不依赖仓库外路径。GitHub 仓库坐标已经带 `yuhaoboris` 命名空间，不需要为了 `npx skills add` 注册同名 npm 包。

Harness 插件携带固定上游提交的两个完整技能及许可证，锁文件记录提交和逐文件 SHA-256；同步脚本和 CI 验证漂移。插件只负责宿主注册、认证 HTTP、简历文本提取和显示；所有业务写入调用原版核心，不在 JS 中重新实现授权或筛选规则。

## 验证

用合成材料覆盖首次使用、只装一个技能、配置冲突、跨进程写入、只看覆盖授权、同公司去重、账号不符、结果不明恢复、待办和已有数据保护。另做独立 Agent 行为检查；真实 Harness 与 BOSS 验证单独报告。
