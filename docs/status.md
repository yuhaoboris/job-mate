## 已验证范围

- 自动化回归使用临时目录、合成工作区与假工具，覆盖脚本状态校验、异常分支、分发及静态规则。规则文字检查只证明规则存在，不证明 Agent 实际遵循。
- 核心流程有真实 Pi 加合成页面 / FakeIM 的行为抽查，覆盖本地对账、原决定的 uncertain、无需动作与已完成决定收尾、禁发与暂停、通知送达分类、无 UI / 偏好不回退、身份与路由拒绝等指定场景。一个 partial setup 草稿完成路径另有抽查。
- 这些抽查没有真实招聘平台、真实 IM、生产调度或第二 runtime；部分场景仅证明安全拒绝，不证明恢复成功。BOSS 局部实测和工具能力记录也不能外推当前全部流程。
- 详细版本、逐场景判档与证据边界见 [验证档案](archive/reviews/2026-11-03-runtime-migration-review.md)。档案不代表正式验收通过。

## 已知限制

- 运行锁与 guard 是业务防线，guard 和平台点击不是原子操作；强互斥与后代清理由 runtime 保证。
- 释放锁后到写入 inbox 之间仍有中断 / 并发窗口，下一轮必须全量对账；缺 attemptId 的事项不按公司或招聘者猜合并。
- 恢复主体与释放分别报告；恢复主体发生未预期编程错误且释放也失败时，尚不保证错误输出同时完整呈现。不得据主体成功推定锁已释放。
- 会话接管判断受页面时间精度与事后补记影响；同一分钟活动可能无法可靠区分，须保守询问。
- 安装更新不保证运行中 Agent 对多个目录的整批原子可见，也不提供断电自动恢复；回滚失败的备份与事务目录须按提示保留核对。
- clarify 排队不等于送达；尚为 received 的答复可能触发最多两次自动唤起，不为减少唤起而伪报已追问。
- 配额上限仍待实测；职位 ID 在不同日期 / 入口的稳定性待观察。疑似重新发布按已联系保守处理。
