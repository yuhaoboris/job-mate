# 通用执行契约

所有 runtime、所有控制方式都遵守本契约。执行工具由 runtime 提供，不能放宽授权、锁、外发证据或收尾要求。开始一轮、输入、可能外发、读取失败及停止时都须核对本文件；同时遵守 [安全边界](safety.md)、[事件记录](ledger.md)、[通知与 IM](notify.md) 和所用技能的平台判据。

## 1. 加锁前能力自检

先读取工作区配置并确认能力，再获取运行锁；自检仅检查工具与环境，不操作招聘平台。

| 能力或条件 | 不满足时 |
|---|---|
| 能读写工作区、运行核心数据脚本 | 不写任何记录、不外发，只能基于已有可读资料筛选并汇报；不以手工改台账替代脚本 |
| 能按工作区指定偏好操作本人日常已登录的可见浏览器，读取、定位、点击、输入并截图核对 | 不操作平台、不回退；仍需本地 inbox、IM 状态或对账时，仅获取 `--no-send` 锁 |
| 能给出可核实的动作结果证据，且适配结果格式已确认 | 缺少外发证据时用 `--no-send` 锁，本轮禁发并说明原因 |
| 配置合法、偏好可满足 | 不合法或不能满足时不操作平台、不静默改配置、不换控制方式 |

browser 当前为空对象或缺失，不要求补设；浏览器能力按 [工作区配置](workspace.md) 与本节自检。选定后整轮不切换控制方式或输入方式，不因失败换工具重发。只读 / L1 由授权表达，本轮完全禁发（含已批准事项）用 `--no-send` 锁。

运行锁与 `guard` 只是业务层防线，不是执行器强互斥。对同一 `runId` 再次 acquire 只沿用原锁，不能把已有可外发锁降级为禁发。运行中能力丢失或结果未知时先收尾、结束整轮，不重取锁继续新尝试。

## 2. 浏览器与目标身份

- BOSS 只使用本人日常已登录的可见浏览器，经辅助功能树或桌面 UI 操作；不使用 CDP、Playwright、无头浏览器、内部 API、页面脚本或请求重放。有头模式、工具名含 browser 都不能证明不走 CDP。
- 不模拟人工、不规避平台检测；节奏、配额和遇限即停按技能与安全规则执行。
- 候选窗口 / 标签页按平台标题前缀定位，不按标题包含某词模糊命中。核对页面结构、可见域名和 `job-mate.json` 的账号 `displayName`；多个候选只在恰好一个账号一致时使用，否则请本人消除歧义。没有候选时请本人打开并登录，不另开浏览器试错。
- 固定已核对的窗口身份。导航、筛选或状态变化后重新观察、获取引用，不沿用上一页编号或历史坐标；视觉定位仅在工具策略允许且目标清晰时使用。
- 控件精确定位在已核对的会话 / 卡片范围内，不在整页按名称点「发送」。运行期间本人和其他桌面 Agent 不同时操作目标浏览器；前台输入还须独占键盘鼠标，后台不抢焦点不代表窗口可同时使用。
- 每次改变条件后确认实际条件和结果内容已生效。等明确可见的状态变化，不高频刷新；可能外发后先观察结果，不把「点击 → 输入 → 发送」合并为一个批量动作。

## 3. 完整读取与否定判断

只有完整读取了目标区域，才能下「没有消息」「输入框为空」「没有人工活动」「卡片后没有已处理提示」等否定结论。范围须覆盖相关消息、输入框、卡片及其内容；无关区域不要求完整。

骨架、交互控件列表、零匹配、单个空值或工具成功都不证明区域为空。截断、缺少完整性证据、完整性字段非法时，继续展开所需范围；仍读不完整就报告未读完，不能推断没有。IM 分页同样适用，未读完不能写成没有新答复。

区分双方消息须结合平台的状态标签与相对位置，不写死坐标；分不清发言人时按技能保守分流，不能据此断言没有接管。读取失败也须先检查本 run 的全部未终结尝试；可能外发后无法证实结果时按第 6 节收尾，不因最后一步只是读取而遗漏尝试。

只读取完成本步所需范围，不反复回显整页；不主动保存或导出完整快照、截图、聊天全文，不把工具完整输出放入汇报、inbox 或 IM。runtime 可能保留本地日志，不承诺零留存，须按私人数据保护。

## 4. 输入与草稿保护

写入前依次确认，全部满足才继续：

1. 核对会话标题中的公司、招聘者与目标一致，且未被本人接管；核对会话之前不读写输入框。
2. 拟发文字是非空、非纯空白的本轮最终版本。
3. 完整读取当前输入框。未知内容不清空，可能是本人的草稿或其他会话残留；跳过并汇报。followup 此时不写 `pending`；apply 若已点击首次沟通，已有尝试按第 6 节收尾。

本轮禁发、no-send、L1 只起草或「只看看」时，不碰产生外发内容的输入框（不输入、不清草稿）；搜索框、筛选项仅可改变显示，不能触发消息或请求。

写入后读回必须与拟发文字完全一致，不一致不发送、不换输入方式试错。读回一致也不证明页面已接收或消息已发出；搜索输入须另核对实际查询结果。发送前再核对会话身份，然后 `guard` 通过后立即执行发送动作。

**写入后不发送的草稿收尾**：仍持锁、未被接管、目标身份可核对且环境可读时，完整读取输入框。只清除能确认是本次写入的草稿：与本次文字完全一致，或可确认由本次写入形成的前缀；清除后完整读回确认为空。其他内容保持原样。无法安全核对或清理时保留现场并报告残留，不绕过停止规则。清理结果不改变发送终态。

## 5. 外发前 guard 与证据三分类

可能外发前先用 `ledger prepare --run <runId> --json '<意图>'` 成功写入 pending，保留返回的 attemptId；禁止 append 动作 pending。限制、授权与原文规则见[发送准备](sending.md)。每个可能外发的动作之前都执行 `guard --run <runId> --attempt <attemptId>`，通过后立即执行；失败就不点击、不新建尝试。首次沟通、发送文字、工具栏发简历、附件确认、卡片同意等分别 guard，不能用一次 guard 覆盖多个动作。等待、卡顿或工具超时后先重新读页面，再 guard；不能沿用旧放行。

一次工具动作不等于一次业务尝试；一个 attempt 可包含多个动作。runtime 须将请求绑定、完整输出、执行状态与环境状态分开判定，不能用窗口不可访问证明动作未执行。

| 动作证据 | 判定与处理 |
|---|---|
| 明确未执行（`not_executed`） | 仅接受已核对契约中的结构化未投递证据，且没有已执行步骤、矛盾或进程异常。可重新观察、定位、guard 后仅重做该动作，同一尝试内最多重做 1 次；仍未执行则停止目标，不能推进后续发送 |
| 可能已执行（`maybe_executed`） | 观察业务结果；无法证实则 `uncertain`，不重试 |
| 未知（`unknown`） | 超时不算未执行；无响应、损坏 / 超量输出、版本未知、请求不匹配、清理未确认等均保守按可能已执行处理，不重发，收尾后结束整轮 |

只有 `ok`、退出码成功、按钮变化、进入聊天页或工具称「点击成功」均不证明业务 `sent`。进程异常时不采用看似完整的输出；runtime 须检查解码、类型、截断、请求与响应绑定、嵌套报告，不能用外层未投递掩盖内层已执行。无法给出明确未投递证据，一律按可能已执行处理。重新定位不能用来重放可能已执行的外发。

## 6. 尝试阶段与停止前收尾

### 首次沟通的正常流程与例外

首次沟通入口本身可能触发平台自动招呼：先 pending、guard → 点击入口 → 观察目标会话 → 输入检查与写入 → 再 guard、发送 → 确认结果。看到平台自动发出的招呼语按技能记录 `sent`；动态补发是独立尝试，不能重用首次尝试 ID。

只有入口动作有明确的正常成功结果、环境可用，且连续观察到身份一致的目标会话，完整读取确认会话为空，才能继续输入。工具「可能已执行」的分类本身不足以证明正常流程。

**放弃发送的例外**：上述正常流程成立、完整确认空会话，且还没有调用后续可能外发动作，或所有后续动作（含重做）都有明确未执行证据时，可按技能记 `failed_no_send`。证据写明公司 / 招聘者、读取范围和空会话依据、放弃阶段与原因、后续未执行动作的错误码。入口失败、超时、身份丢失、观察不连续或后续动作有任一次可能已执行 / 未知时，即使后来读到空会话也不适用，只能保守 `uncertain`。

回复在会话、接管、非空文字与空输入框检查通过后才写 pending。简历 / 卡片按平台语义确认：请求已发、附件送达、对方已查看分别记录，不套用文字新气泡判据；卡片后已有已处理提示不再点。

### 全部尝试收尾表

任何停止分支（含只读命令失败、单目标停止、整轮结束）之前，先检查并收尾本 run 全部未终结的 attempt，不仅是最后一个动作。

| 已知情况 | 终态 |
|---|---|
| 已有终态 | 不覆盖，保持原 attemptId |
| 已观察到本次明确发送成功证据，尚未落终态 | `sent`；写明新消息内容与「送达 / 已读」或对应卡片证据，优先于任何停止原因 |
| 没有调用过任何可能外发动作 | `failed_no_send`；写明停在哪一步及未点击原因 |
| 所有可能外发动作都有明确未执行证据 | `failed_no_send`；逐个记录工具错误码与依据 |
| 满足上面的正常流程放弃例外，或页面按技能明确显示发送失败 | `failed_no_send`；记录对应证据 |
| 其他可能已执行、未知、无法证实结果 | `uncertain`，请本人核对；停止重发，followup 按规则暂停会话 |
| 本轮没有尝试 | 不写动作事件 |

「重新读取后没看到新消息」不是未发送证据。已有成功证据不因后续截断或环境错误抹掉；`uncertain` 只由本人核对后以原 attemptId 追加终态，不能换工具、换 run、换事项规避阻断。

逐个收尾后按 [释放与对账契约](ledger.md#释放与对账契约) 释放：检查退出码、`released`、`reconciled`；按 attemptId 对照最新 `threads.unresolved` 和 inbox，保留原决定 ID，缺 ID 的历史事项先待对账，不按公司猜合并、不重复建事项。释放失败保留锁、报告持锁者和主体 / 收尾各自错误，不宣称完全收尾。释放后只做本地收尾与通知，不持原锁重发。下一轮入口即使 `reconciled` 为空也须全量对账，补齐释放后写 inbox 前中断的事项。

## 7. 环境受阻、通知与恢复

窗口不可访问、工具不可用或输出未知时，先按第 6 节给全部尝试收尾，再结束整轮，不新建尝试。不能单凭窗口错误确诊锁屏，报告「可能锁屏、窗口不可见或浏览器未运行」及实际证据。

纯环境受阻不全局暂停；若已看到验证码、风控、安全验证、登录失效或账号不符，仍优先按 [安全边界](safety.md) 全局暂停，额度提示按既有规则停止，不以环境错误降级安全信号。

- 事项先写 inbox，再经 outbox 通知；同一个键去重只发一次。排队和交付 runtime 不是已发送，送达不明不自动重发；仅在 [通知契约](notify.md) 允许的冻结路由、原幂等键及本人确认窗口内处理例外，不临时扩大保证。
- `uncertain` 按 [通知与 IM](notify.md) 的结果不明事项处理，执行决定产生不明结果沿用原 ID、原结论及对应结果版本，环境提醒不能代替核对事项及其通知。
- 环境提醒键固定为 `env-blocked:<日期>:<原因代码>`，日期用工作区时区的 `YYYY-MM-DD`；同日同原因只排队一次，不同原因分别报告。
- 尚无阻断终态、只是暂时无法执行的答复保留 `ready`；已形成 `uncertain` / `failed_no_send` 的按 notify 收尾分流处理，不承诺环境恢复后自动续发。
- `im.channel: none` 时仅本地 inbox 和汇报，不投递 IM。无 IM 或投递失败也不能遗漏最终汇报的三项：原因、环境恢复办法、恢复后如何重新发起。请本人恢复可见窗口 / 登录或处理权限、版本、工具状态；清理未确认先确认旧进程及后代停止。手动运行由本人重新发起；runtime 唤起且仍有待处理答复时，经其可用入口请求重试，不能绕过对账与状态门禁。本人确认恢复后，任何外发前重新执行去重与状态检查；恢复本身不解除 uncertain，不重放上轮动作。

## 8. runtime 调度与进程收尾

核心数据脚本只维护状态，不操作工具、不访问网络、不后台等待或常驻。调度、等待循环、进程单实例、超时、后代进程清理与防睡眠归 runtime；做不到时不设置无人值守唤起。

runtime 须在启动前排除旧实例并阻断状态不明的旧运行；主进程退出不证明后代停止，超时或清理信号已发也不证明清理完成。确认整个受管进程树停止后才允许新一轮，通知状态遵守 [通知契约](notify.md)。权限拒绝或探测不明不能算进程消失；只清理自己管理的进程，不影响无关进程。不按经过时间猜旧实例已停，不以强杀后立即重启制造并行。

锁 / guard 与点击之间并非原子操作，不能当作执行器单实例证明。runtime 自检、工具适配和静态规则测试通过均不等于真实 Agent 行为或正式验收通过；执行方式、版本或流程改变后须按新边界重新验证。
