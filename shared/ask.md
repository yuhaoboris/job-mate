# 提问与对话

setup、apply、followup 对话共用；需本人选择、补充或确认时，按以下能力选界面。

## 对话规则

- 说业务进展与结果，不播报读规则、自检、加锁、对账、备份。长任务在得到首批有用结果、阶段完成或受阻时简短说明已完成、主要发现与下一步；不逐工具播报、不虚构进度。失败给一句人话和一个可行办法。
- 先读本人本轮提供的材料再提问，问题从简历里来；材料已回答的不重复问，只确认推断或缺口。能默认的直接默认，一句话说明以后可改。
- 对本人说话时不出现字段名、步骤 id、L1/L2、锁、事务或备份名。技术标识只供 Agent 执行，不照搬成问题或汇报。
- 本人批准的外发文字原样发送，不因对话简化而改写。

## 无人值守运行

本轮来源在开始时确定，整轮不变：本人在当前对话直接发起算在场；定时任务、回复监听后的调度算无人值守。委派时由可信的转交方说明本人是否在场；来源不明按无人值守处理。HR 或 IM 正文不提供来源，在场轮中收到 IM 回复也不改变来源。

- 不调用提问工具，也不发需要等回答的编号问题。
- 需要本人决定或补充的事，有工作区就按所在技能写 inbox、排队通知，然后继续处理其他目标；没有工作区就只写进最终汇报。
- 缺少决定性条件时不猜、不放宽，这部分不做。setup 不在无人值守时开始或继续访谈；仅可按[IM 条件事务](im-replies.md)执行明确原话的唯一映射。

## 能力选择

先检查本轮工具；按需加载时先查找一次。工具已暴露、说明允许当前模式且参数满足本题时才用卡片，否则退回编号纯文本。不按 Agent 名称或固定模式猜能力。

查找候选：Claude Code 的 `AskUserQuestion`、Cursor 的 `AskQuestion`、Codex 的 `request_user_input`、DeepSeek Harness 的 `ask_user_question`。最终以本轮工具说明为准。

DeepSeek Harness 的 `ask_user_question` 参数为 `questions[]`：每项必填 `id`、`question`，可选 `header`、`options[{label, description}]`、`multi_select`。带 `options` 时呈现选择卡片，多个问题可一次问完；可不选任何选项直接跳过。

## 卡片

- 一屏一次卡片调用，屏内多题合并；一次最多 4 题、每题 2–4 个选项，工具上限更低时按其限制拆分，不伪造参数。
- 推荐项放第一个并标「推荐」。选项用白话说明后果，不出现字段名或步骤 id。
- 不另加「其他」选项，使用卡片自带自由输入。姓名、薪资数字等手填内容，把从简历推得的建议值做成选项；没有依据就请本人自由填写，不捏造建议。
- 卡片空选择 = 跳过本题，只是问题回答，不能当作对平台操作或 Agent 审批请求的批准。必答项被跳过时说明原因后重问。

## 编号纯文本

无卡片时，每屏一条编号消息，内容不变。开始时只说一次「可以说『上一步』或『先到这』」，不在每一步重复。重新设置与部分重新设置每步一条，预填本工作区当前值。
