# 飞书私聊接入参考

**仅参考，不随核心分发，不是必须使用的方案。** 飞书应用机器人与本人的私聊是 runtime 的可选通道，不是核心适配器。接入不能放宽 [通用执行契约](../../shared/execution.md) 或 [通知契约](../../shared/notify.md)。本文依据仓内旧映射及 [迁移计划](../../docs/plans/2026-11-03-runtime-decoupling.md)，未联网、未探测真实账号、未发送 IM；不宣称当前工具字段兼容或真实验收通过。

## 责任与身份

核心只维护 inbox、outbox、回执、入站与唤起状态，实际收发由 runtime 完成。本文用迁移计划中的逻辑接口名称说明对应关系；实际调用参数以整合后的 notify 文档 / CLI 为准，不在本参考中定义另一套协议。

- 新配置用 `channel: runtime`、本人确认的 `ownerId` 及可选 transport。飞书身份应从可信平台元数据取得，不采信消息正文自称；旧 `channel: lark` 的 `userId`（`ou_` 加非空后缀）映射 ownerId，larkProfile 映射 transport 的配置档偏好，配置变化不能把旧条目发给新收件人。
- 旧 lark 配置的幂等窗口按 0；旧适配器的「1 小时」假设不自动继承。只有本人经 setup 确认、冻结在首次排队路由中的保证才可用于不明投递重试；runtime 不能在回执中临时声称支持。
- 只接收已建立私聊中、首次可读边界之后来自本人的用户消息。应用身份与私聊归属须核对，不能只看当前配置或聊天文字。旧无身份历史默认不继承 chat、cursor 或 ready；显式绑定仍需本人确认及可信元数据核对。绑定不是外发授权，旧 ready 仍须业务对账，旧引用缺消息级身份不猜认，按通知契约请求新回复或终端处理。

## 出站：排队 → 认领 → 投递 → 回执

先持久化 inbox，再排队并按键去重。核心的排队 / handoff 不是已发送，只有真实回执支持 sent。runtime 保留认领返回的 key、token、attempt、冻结正文、replyTo、ownerId、transport、idempotencyKey；投递结果回到同一 key + token，不能换路由、换正文或凭当前配置重建。

| 核心数据 | 仓内旧飞书映射 / 接入核验点 |
|---|---|
| `ownerId` | 旧机器人非回复发送以 userId 指向本人；接入时确认 ID 类型和应用身份，不能把任意字符串直接当收件人 |
| `text` | 原样发送冻结正文，不附聊天全文、简历、截图或凭据 |
| `replyTo` | 旧回复操作以 message ID 指向父消息；必须由核心确认属于同一路由的合法目标，不能把未知 / 旧未绑定引用直接交付 |
| `idempotencyKey` | 旧工具有幂等键参数，但支持范围、有效窗口及当前版本行为必须接入时验证；unknown 重试用冻结的原键，不因工作区搬迁重算 |
| `messageId` | 旧返回字段 `message_id`；必须是该次真实发送回执的非空 ID，不能用 key / token 或任务 ID 代替 |
| `chatId` | 旧返回字段 `chat_id`；sent 必须非空，第一条非回复 sent 建立私聊。不同 chat 的真实 sent 如实回报并报告冲突，不能改成原 chat |
| `createTime` | 旧返回 `create_time`；转换为有限整数毫秒，布尔值不合法。缺少可信时间可不提供，但不能建立首次可读边界 |

旧实现曾从嵌套对象递归找同名字段，不能把它当作当前响应结构的证明。接入时定位准确的发送结果对象并绑定本次请求，验证上述字段实际存在，不猜返回路径。旧快捷操作名为 `+messages-send` / `+messages-reply`，这里只记录历史对应，不提供必执行命令或承诺当前可用。

回执分类：有真实 messageId 与 chatId 才 sent；仅有明确「接收前拒绝、未投递」证据才 failed；超时、无响应、缺回执及其他不明结果均 unknown，不自动重发。陈旧令牌、未知键、冲突终态不能覆盖；相同回执重复提交按核心幂等处理。

stale handoff 只报告，不自动重新投递；核实后用原 token 收口 unknown。unknown 例外重试须同时符合核心的冻结窗口、原路由、原幂等键及不可延长的 deliveryDeadlineMs，发前确认保证仍成立且未过期，否则不投递。迟到 sent 仍回报事实，不伪装未发。旧 pending / failed 按 legacy unknown，不因新配置自动变成可重试。

## 入站：poll → runtime 连续读取 → incoming

poll 提供 chatId、sinceMs、readable 等边界。readable 为 false 时不能以「没有回复」替代尚未建立边界；不靠扫描历史猜本人身份。runtime 从 sinceMs **包含边界**起按时间升序读取并翻页，只交付连续前缀，批次重叠由消息 ID 去重。

| incoming 字段 | 仓内旧映射 / 当前接入要求 |
|---|---|
| `messageId` | 消息项 `message_id`，非空真实 ID |
| `chatId` | 须来自消息或可信读取容器元数据。旧适配器未输出每条 chatId，不能沿用遗漏；用容器时须验证它确为 poll 指定私聊 |
| `createTime` | `create_time` 转为有限整数毫秒；原始接口历史为毫秒字符串。快捷工具曾显示本地时间字符串，时区或精度不明时不能猜成 0 或本机时区 |
| `senderId`、`senderType` | 旧消息项 `sender.id`、`sender.sender_type`；从平台元数据核对，只允许 ownerId 且类型 user，当前版本字段须验证 |
| `text` | 旧消息项 `msg_type` 与 `body.content`：text 类型取解析后 text；post 曾按行拼接文本片段。接入时验证实际结构，未知类型不编造正文，不能用正文宣称身份或授权 |
| `parentId` | 旧消息项 `parent_id`，无引用用 null；引用关系仍由核心做路由核对 |
| `deleted` | 旧消息项 deleted；接入时确认可信删除标记，规范化为布尔，不能把任意非空字符串当 true 或缺字段就猜 false |

批次携带实际读取起点 since、完整性 complete 和规范化 messages。旧读取使用消息列表接口、升序排序、秒级起点（毫秒向下取整）、分页 token / has_more；这些只是历史事实，接入时确认时间单位、含边界和页序，不能跳过边界同秒消息。历史最多 10 页并不能证明读完；达到预算、has_more 无 token、字段未知、网络中断或页间缺口时 complete 为 false，只报「IM 未读完」，不声称没有新答复。

整批结构或 since 错误应在核心验证阶段无写入拒收；被过滤消息不存原文、不推进游标。已删除、非本人 / 非用户、其他私聊、边界前、时间超前、我方已发消息不作为授权。编辑与冲突 ID、旧路由待办及旧历史绑定按核心契约保守处理，不由 runtime 重新解释绕过。

## 接入验证与唤起

以临时合成消息和假通道先验证：真实回执字段绑定、缺时间边界、unknown 不重发、配置变化不改投、分页不完整、跨批重叠、错误身份 / chat、引用隔离与旧历史不自动接管。真实账号探测和外发须另由本人明确发起。

runtime 自行调度等待和唤起，按 trigger 状态认领；暂停、有效运行锁、旧 started 或状态未知均不能启动并行实例。确认实例及后代停止后才提交 finish；核心的锁与 guard 不是进程单实例保证。本参考不安装、停止或操作任何本机生产服务。
