# BOSS 直聘：通用页面要点

页面会改版。以下来自已有使用记录；与当前页面不符时按实际页面判断，并在汇报中注明差异。机器可读描述见 [platform.json](platform.json)，筛选与首次沟通见 [apply.md](apply.md)，会话巡检见 [followup.md](followup.md)。

## 访问方式与账号

- 从 `https://www.zhipin.com/` 或本人提供、核对过域名的职位链接进入。
- 不使用 CDP / Playwright、无头浏览器：此前使用 CDP 曾被重定向到 `_security_check` 后页面空白。只用本人日常已登录的可见浏览器，经辅助功能树或桌面 UI 操作；工具选择遵守[浏览器入口](../../shared/browser/README.md)。
- 账号名在页面右上角头像附近，与 `job-mate.json` 的 `displayName` 核对；登录、扫码和验证由本人完成。

## 职位链接与招聘者写法

- 职位卡片的职位名带链接，形如 `https://www.zhipin.com/job_detail/<id>.html`；`<id>` 即 `jobId`（已有本人确认记录）。通过辅助功能树读链接；独立职位页可读可见地址栏。
- 列表链接不可读或复制链接菜单不可用时，`jobUrl`、`jobId` 记 null，不通过其他接口补取，不猜测、不拼接。
- 链接可能带 `lid`、`securityId` 等随会话变化的参数；观察/筛选交给 append，外发意图交给 prepare；脚本按平台描述规范化。
- 公司通常显示简称，按页面原文记录，停止名单靠别名匹配。
- `recruiter` 只写「姓名(职务)」，如 `张先生(人事行政专员)`；不混入时间、公司名、`[送达]` 或消息摘要。

## 薪资原文

常见写法：`8-13K`（月薪千元）、`8-13K·13薪`（13 薪不计入月薪比较）、`150-200元/天`（日薪，不直接当月薪）、`面议`（未知）。

搜索结果列表的薪资在辅助功能树中可能是特殊字符。用截图核实或以可核对的职位详情为准；读不清记未知，不根据乱码推测。

## 输入与发送

- 核对会话标题中的公司、招聘者与目标一致后再读写输入框。
- 切换会话后文字可能残留，草稿归属无法从输入框判断。列表有「草稿」标记或输入框有未知内容时，本轮跳过并汇报，不清除、不发送残留内容；按[输入与草稿保护](../../shared/execution.md#4-输入与草稿保护)收尾。
- 聊天输入框的本地控件标识曾为 `chat-input`，须现场重新核对；这是页面定位事实，不指定工具调用。空框时「发送」也可能 enabled，不用按钮可点证明有内容。
- 输入后单独读回完整文字，再分别 guard、点击发送；不把输入与发送合并。一次只发一条，不拆成多个气泡。

## 工具超时与结果

点击沟通或发送后，工具超时、重置、切走前台标签页，都不证明未执行。按[外发证据三分类](../../shared/execution.md#5-外发前-guard-与证据三分类)及本轮技能的结果不明停止规则处理，不重放最后一次点击；需要本人核对时保留原尝试。

文字消息的发送证据是：会话出现本次新消息并显示「已送达」或「已读」，或针对当前职位的成功提示。仅进入聊天页、按钮变化不算；卡片和附件使用各自的结果证据。
