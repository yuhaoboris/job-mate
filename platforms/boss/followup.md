# BOSS 直聘消息页（followup）

页面会改版。以下来自此前的使用记录，首次按本技能运行时核对，与实际不符时按页面判断并在汇报中注明差异。通用的访问方式、账号核对、招聘者写法、输入与发送规则见 [common.md](common.md)。下文 SKILL.md 指本轮 followup 技能。

## 消息列表

- 从网页右上角「消息」进入。列表每项显示时间、招聘者姓名、公司、职务和最后一条消息摘要；有未读消息的会话带未读标记。
- 列表懒加载，向下滚动加载更早的会话。摘要前缀 `[送达]` / `[已读]` 表示我方最后发言；没有这些前缀是 HR 最后发言的候选，须打开会话确认，不能仅凭未读标记或截断摘要断言。
- 置顶项可能很旧，不参与「连续 3 个非置顶项超龄」的停止计数；按技能的旧会话扫描上限、日期范围和风控停止条件执行。
- 摘要可能被截断，必须点开会话读完整内容。
- 列表「草稿」标记表示该会话有未发送内容，所有 runtime 都不清除，本轮跳过并汇报；切换会话后文字可能残留，按通用输入契约先核对会话、保护未知内容。聊天框本地标识曾为 `chat-input`，须现场核对；空框「发送」也可能 enabled，不用按钮可点证明有内容。

## 筛选与搜索（2026-10-29 实测）

- 消息页有「全部 / 未读 / 新招呼」等筛选。巡检时先用「未读」找有新消息的会话；「新招呼」里是 HR 主动发起的会话，按 SKILL.md 第 4.2 节评估职位。
- 联系人搜索只覆盖最近 30 天。更早的会话要在「全部」列表中滚动查找；找不到时在汇报中写明检查范围，不能写成「没有这个会话」。

## 会话

- 会话标题显示招聘者、公司和沟通的职位；职位名通常可点开查看详情。
- 我方消息在右侧，气泡旁显示「送达」或「已读」；HR 消息在左侧。所有 runtime 判断双方时，状态标签与左右位置两者都符合才下结论，左右只做相对比较，不写死坐标；对不上按「分不清发言人」处理，不能据此登记或断言没有接管。
- 往上滚动加载历史：分诊从我方第一条或最近 20 条起，有遗留事项线索继续追溯；基线另从末尾读到 HR 一条文字、开头或我方连续 3 条即停。开始前记 `readAt`，两种读取不互相替代。历史无法加载或分不清发言人，本轮不登记。
- 页面可能只显示日期；基线时间取当天 23:59:59，接管判断则取全天区间。「10:00」取一分钟区间。今天 / 昨天等标签先按页面日期定位，不能当成精确时刻。
- 接管按 SKILL.md 第 4.3 节的 `boundaryAt`：先匹配所有本地 sent（含分界那条），同类且时间在页面区间前后 2 分钟内算 Agent；不匹配的区间早于分界为历史、晚于为本人、跨界暂停询问。既检查文字，也检查发简历、同意联系方式、接受面试等卡片操作；时间或执行者看不清按无法判断。
- 交还记录的 `acknowledged` 只豁免同时间标签同类型从早到晚前 count 条跨界活动，不豁免新活动：上午确认一天标签 1 条，下午新发「14:00」算接管；仍只显示日期的第 2 条再次暂停。交还分界仍是 released 事件时间，不推到未来。

## 时间标签与消息身份

- 会话可能显示「10:32」「昨天」「今天」或明确日期；标签作用于其后的消息，直到下一个时间标签，按页面顺序归组。日期上下文与时分分别核对；孤立「10:32」不能自行当作今天。
- [platform.json](platform.json) 的 `timeLabels` 保存已有相对标签、星期、日期和时分组合的词表与格式。原始标签与读取时刻一起保留为核对依据，不把只有日期的标签当成精确时刻。
- 页面是否暴露稳定消息 ID **待本人实测确认**；当前描述为 `messageId.available: false`。不拿内容摘要、列表摘要或本地控件编号冒充平台稳定 ID，不声称能识别所有同文撤回重发。

## 请求卡片

HR 可能发来需要点按钮的卡片。**点击前先写 `pending`**，因为点「同意」就是外发。

| 卡片 | 处理 |
|---|---|
| 请求交换微信 / 电话 | 不点同意，写入 inbox |
| 请求发送简历 | 按 SKILL.md 第 5.2 节：选对版本后同意。**已处理过的请求卡片仍可能显示「拒绝 / 同意」按钮**（2026-10-29 实测）：先看卡片之后有没有「附件已发送」「对方已查看」等提示，有就说明已处理，不要再点；只凭按钮还在不能判断未处理 |
| 面试邀约 | 不点接受，写入 inbox |

## 发简历

- 我方主动发：会话工具栏中的「发简历」，选择已上传的附件后确认。此前记录显示会先出现「请求待同意」，对方同意后附件才送达。
- 附件状态分别记录：请求待同意（`resume` 的 `sent`）、附件已送达（`observe/resume_delivered`）、对方已查看（`observe/resume_viewed`）。
- 只能选平台上已上传的附件；附件名与 `resumes/index.yaml` 的 `uploaded.boss` 核对一致后再发。
