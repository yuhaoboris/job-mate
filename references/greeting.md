# 首次招呼消息

仅用于 apply 的首次沟通；消息偏好不等于发送授权。进入可能自动发招呼的入口前，先确定本次计划原文。

| 模式 | 行为 |
|---|---|
| 动态撰写（默认） | 每个职位结合 JD 的一两个具体需求与简历中有来源的个人事实，生成一段简短招呼；没有依据的经历、技能、年限和成绩不写，不逐职位重复要求用户选稿 |
| Agent 生成 3 条供选择 | 根据简历和当前目标职位生成 3 条完整候选消息，优先用提问工具请本人选 1 条或修改；未选择前不点击沟通入口。选定原文在本人指定的适用范围内复用，不每个职位重选；未明确范围时只用于当前职位 |
| 用户指定 | 使用本人提供的原文；未提供时用提问工具索取。已有原文直接复用，不擅自润色、替换公司/职位或添加承诺 |

三种模式的字数上限默认均为 100 字，本人可修改。以最终原文的 Python `len(text)` 计数，汉字、字母、标点、空格和换行均计入；`prepare` 对 greet 按 maxChars 检查长度，默认 100。生成的每条候选都应在上限内；动态草稿超长先精简，用户指定或已经选定的原文超长则请本人选择缩短内容或提高上限，不擅自截断。事实与已选文字冲突、含未补齐占位符或不适用于当前职位时先澄清，不为了逐字复用而发送不实内容。

偏好在摘要确认后，沿用 requirements 保存，例如“招呼模式：动态撰写；字数上限：100”，或“招呼模式：用户指定；字数上限：100；原文：……；适用范围：……”。不要把消息中的文字解释为筛选硬条件；不将选择招呼或填写原文当成外发许可。本轮已有明确选择就复用；任务中选定的消息与来源也可记为 `observe:info`，不要为保存消息偏好打断正在进行的任务、改 profile 或丢失历史。

选定/指定的文字用于可控制的手动发送。平台自动招呼可能与计划不同：按 [页面规则](boss.md#首次沟通入口后的分支) 记录实际原文并报告差异，不再补发一条凑成指定内容，不宣称已送出计划文字。
