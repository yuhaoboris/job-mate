# 浏览器操作与页面核验

## 浏览器选择

开始浏览器操作前，检测本地命令：macOS/Linux 用 `command -v`，Windows PowerShell 用 `Get-Command`。

1. 优先使用 `ego-browser`（ego browser）。
2. 仅当本地找不到 `ego-browser` 时，回退到 `agent-browser`。
3. 两者都未安装时，告知缺失工具，等待本人安装；不自动安装。

先读取所选工具的 `--help`，按其支持的方式连接本人已登录的可见浏览器。已安装但连接失败、未登录或遇到平台限制时，报告具体阻塞，不以切换工具绕过。

## 搜索页面访问

同一账号沿用原工作区。先复用当前页面已经渲染的文字和本地筛选记录。需要加载新内容时，在同一可见标签页逐次操作，每次先按[数据命令](protocol.md#搜索访问)登记。

- **列表访问**包括首次加载搜索结果、切换城市或关键词、翻页、触发滚动加载，以及返回时重新加载列表。只读已显示的卡片可以一次完成。
- **详情访问**包括直接打开职位链接、点击卡片，以及会加载 JD 的悬停或侧栏预览。本轮和最近一小时内，同一职位只登记一次。先写下要核实的事项，再打开对应岗位，只按实际看到的字段更新记录。
- 登记成功才执行这一次操作。不要预先领取多次许可、并行开标签或用脚本遍历卡片触发加载。加载失败也占一次，使用已有卡片标记待核实。间隔未到就先做本地筛选，仍有必要时等到返回的时间再访问。达到上限就交付本轮进度，不排队等额度刷新。

## 访问受限

平台弹窗、验证页或本人提供的同类提示出现「操作过于频繁」、验证码、异常行为、暂时禁止使用等信号时，立即停止搜索、只读浏览、会话检视和外发。用 `restrict_access` 保存提示原文及页面给出的恢复时间，即使尚未开始阶段也能登记。仅用已取得的证据记下待核实岗位和外发结果，再在本地收尾。不要刷新探测、换工具重试或预约到点自动访问。

平台给出恢复时间时，最早在该时间之后、本人再次要求继续时恢复。没有明确时间或需验证时，等本人确认已恢复访问。按[恢复命令](protocol.md#决定与恢复)解除记录后，从已保存的候选和会话进度接续。仅提示新招呼额度用尽时，停止新招呼，仍可处理已获授权的既有会话。

## 外发核验

用页面账号、公司、职位和招聘者确认目标。登录、验证码和系统权限由本人处理；只操作可见页面，不用隐藏接口或绕过平台限制。

页面发送与本地写入不是原子操作：先按[数据命令](protocol.md) prepare，每次可能外发前 guard，事后以页面证据 finish。结果不明时不重发。

## 首次沟通入口后的分支

「立即沟通」可能自动发出招呼。点击后查看会话、消息时间和状态，页面跳转不代表送达。

| 页面结果 | 处理 |
|---|---|
| 本次招呼已发 | 登记实际原文，只计一条，即使与计划不同也不补发。 |
| 点击前已有沟通 | 不算新招呼；按最后一条消息决定回复或跟进。 |
| 历史已加载，确认未发 | 固定语或动态语发准备好的原文；平台预设用页面快捷语，不输入意图标记。预设不可用则跳过并说明。 |
| 已有草稿 | 保留草稿，跳过该会话。若入口可能已外发，仍核对结果。 |
| 加载中、超时或结果不清 | 用当前可见证据核对。仍不明则登记不明、暂停外发。仅在账号可正常访问时继续检视会话。 |

手动发送前核对会话、输入框和原文，确认没有迟到的自动招呼。发送后据气泡和状态[登记结果](protocol.md)。
