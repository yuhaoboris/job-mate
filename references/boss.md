# BOSS 页面核验

在本人已登录的可见浏览器操作。用页面账号、公司、职位和招聘者确认目标；同一公司可能有多个岗位，不能只按公司名判断。登录、验证码交给本人处理，遇到平台限制如实报告。

## 首次沟通入口后的分支

「立即沟通」可能只打开会话，也可能已经发出招呼。点击前记录这次发送意图，核对目标；点击后看当前会话的消息、时间和发送状态，不以页面跳转当作已发送。

| 当前页面看到什么 | 下一步 |
|---|---|
| 出现本次已发的我方招呼 | 记录实际原文，只计一条。即使平台自动语与计划不同，也不另补一条。 |
| 看到本次点击以前已有的沟通 | 不计为本轮新增，不再发首次招呼。按最后一条真实消息判断是否需要回复或跟进。 |
| 会话历史已加载，能确认这次没有发送 | 固定语或动态语：只发准备好的那一条。平台预设：调用页面可用的预设，不把「使用平台预设」等内部文字输入聊天框。预设不可用则跳过并说明，不擅自代写。 |
| 原有草稿，不宜继续输入 | 保留草稿，跳过该会话，继续检视其他会话。若入口本身可能已外发，仍按实际结果登记。 |
| 页面未加载、发送中、点击超时，无法判断结果 | 只读核对；仍不明则登记不明，不再点击或补发。暂停外发，不等于停止只读检视；若消息列表仍可访问，继续看到末尾。 |

手动发送前确认当前会话、原文和输入框，检查是否出现迟到的自动招呼。发送后看已发气泡与状态；台账操作见[数据命令](protocol.md)。
