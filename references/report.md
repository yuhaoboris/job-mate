# 汇报格式

只列本轮涉及的部分，省略空表。花括号替换为实际内容；结果分为已送达、确认未发、结果不明，仅已送达计入发送数，不明单列说明。有待确认的时间时先列「时间安排」，再报会话和岗位进展；其他需本人决定的事项另列。

## 交付渠道

当前会话始终交付完整报告；若本地安装了 Hermes Agent，同时通过其 `default` profile 已配置的消息渠道，把同一份报告发送给用户本人（如飞书），供手机接收通知。用户明确不需要通知时跳过。

1. **检测工具。** macOS/Linux 用 `command -v hermes`，Windows PowerShell 用 `Get-Command hermes`；未安装则仅在当前会话汇报，不自动安装。
2. **确认渠道。** 先读 `hermes --help`、`hermes send --help`，再用 `hermes -p default send --list` 查看可用目标。明确指定 `default`，不沿用当前激活的其他 profile，也不更改配置。复用本人已指定的收件目标（可保存在 `profile.requirements`）；否则仅在能确认是本人且目标唯一时直接使用。多个渠道、群聊或收件人不明时先询问，不广播、不猜账号。未配置渠道则说明通知未发送。
3. **发送同一报告。** 将报告保存为工作区内的 UTF-8 文本文件（建议放在 `<workspace>/reports/` 下），执行 `hermes -p default send --to <已确认目标> --file <报告绝对路径> --json`，用独立参数传入路径和目标，不把报告正文拼进 shell。使用 Hermes 的渠道投递能力，无须另开模型会话改写报告；不附加简历原件、聊天全文或凭据。
4. **核对结果。** 在当前会话注明 Hermes 通知成功、失败或结果不明；命令成功不代表用户已读。失败或渠道不可用不影响本轮汇报，结果不明不盲目重发。

通知本人属于汇报，不计入招聘平台的新招呼、回复或简历发送数。
